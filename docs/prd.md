# 产品需求文档（PRD）

> 恢复版（2026-10-14）：依据旧任务保留的正文与修订重建。除原始方案外不声明字节级一致；涉及实现的描述是应恢复的设计，需与恢复代码及新测试对齐。旧主机结果不证明本目录已通过验收。

## 1. 产品主张

面向想用 AI 完成一件具体事情、却不知道从何开始的用户，提供经过编辑核对的工具建议，以及可以直接尝试的 Prompt、步骤和工作流。

最小交付单位是“下一步能做什么”，不是工具名清单。惊喜来自发现适合目标的工具，不来自概率奖品或价值悬殊的抽取。

| 用户兴趣                | 用户任务                     | 结果需要说明                           |
| ----------------------- | ---------------------------- | -------------------------------------- |
| Video Creator / creator | 把一段素材变成清晰的内容草稿 | 先做什么、素材怎样处理、发布前检查什么 |
| Developer / developer   | 形成可验证的软件原型或改动   | 怎样组织输入、审查代码和测试           |
| Student / student       | 从资料形成理解与复习路线     | 核对原文、自测、遵守学术规范           |
| Business / business     | 整理资料、写作或减少重复劳动 | 数据边界、输入输出、人工审批点         |

兴趣是用户主动选择的任务入口，不是职业、年龄或敏感属性推断。Student 不等于未成年人，本轮不收集年龄、学校或身份资料。

## 2. 阶段范围

最新工程要求：NestJS后端 + MongoDB + 独立运行/构建/部署的Next.js用户前台与独立Next.js管理端（shadcn/ui + Tailwind），合计web/api/admin三个应用，见[当前需求](requirements.md)。原方案数据库选择已由最新要求覆盖。

### 阶段 0：发现与交易闭环

- 英文 Landing Page，说明价值、流程、四种兴趣与透明套餐边界。
- 16 条真实工具种子，处于原方案 10–100 条范围；各兴趣至少 4 个候选。
- MongoDB显式初始化/seed后从数据库加载目录；MemoryStore 使用同一版本化目录。
- 兴趣必选，目标可选，支持免费与 Premium。
- Free 默认 1 个推荐，包含理由、场景、Prompt、步骤。
- Premium 默认 3 个不重复工具，包含组合工作流。
- PayPal 创建订单、批准、服务端 capture 和核验后履约。
- Vercel AI Gateway（唯一真实AI入口） 结构化生成；本地有明确标记的 demo。
- Resend 事务邮件；Box 邮箱可选，发送需明确同意。
- 支持失败、取消、重复操作与重试；点击按钮不等于付款完成。

### 阶段 1：保存有价值的发现

邮箱验证码登录、服务端会话与退出、历史 Box、工具收藏增删、按身份隔离访问；匿名结果通过独立访问凭证读取并可在登录后认领。

### 当前追加：独立管理端

提供独立登录的第一方运营视图，回答“有没有人在使用、哪些兴趣被选择、是否有账户留存线索”。管理端从 NestJS 读取真实活动与账户记录，提供统一 UTC 日期筛选、汇总、用户和事件报告。邮箱验证码登录只证明账户身份；只有服务端管理员角色能访问报告。

空库显示零与空状态，不用演示数字伪装经营情况。匿名访客只代表短期浏览器标识；漏斗各列是窗口内独立计数，不能直接解释为同一批人的转化率。模拟、PayPal sandbox 和 live 必须分清，当前不计算净收入。用户邮箱仅管理员可见，不进入公开页面。具体字段和访问边界见[管理端说明](admin.md)。

### 不在本轮

订阅扣款、社区、公开画像、复杂 Agent、代执行第三方工具、Growth Agent、自动推广发帖、联盟返佣管理、原生 App、代开第三方账号与许可证销售。

## 3. 用户旅程

### 免费体验

1. 从首页进入发现页，选兴趣并可补充目标。
2. 选择 Free，服务器校验参数、限流并从目录生成建议。
3. 结果页提供下一步、可复制 Prompt 与官方链接。
4. 登录后保存发现；首次体验不强制账号。

### Premium

1. 付款前显示服务端价格、USD、一次性购买和内容边界。
2. 创建本地订单，锁定金额、币种、brief、档位和供应商幂等键。
3. 用户在 PayPal 批准；demo 必须明确不实际扣款。
4. 回站后由服务器 capture 并核验，客户端 success 参数不能解锁。
5. 付款确认后生成；重复 capture 对应同一履约结果。
6. 邮件失败不隐藏已付费结果，也不再次收费。

取消付款不是退款。付款未确认不得显示已付费；付款已完成但生成失败，应保留订单并从原订单恢复，不要求新付款。

### 登录与保存

主动提交邮箱 → 收到登录码 → 验证未过期且未使用的码 → HttpOnly 会话 → 历史与收藏 → 退出使会话失效。

登录事务邮件、Box 结果邮件和 Newsletter 是三个不同用途；前两者不构成营销订阅同意。

## 4. 结果质量

每个推荐必须回答：为什么适合、可以完成哪项任务、可以复制什么 Prompt、顺序是什么、哪些结果需人工核验、外部费用或限制在哪里确认。

Premium 应形成可传递产物的流程，如提纲 → 初稿 → 检查，不应只是三个同类工具。模型只能返回目录工具 ID，不编造工具、价格或外链。服务器核验数量、去重、兴趣与 workflow 引用。

使用指南必须说清手工复制、导入、导出、审核；不能暗示已自动执行集成。工具不接受文本 Prompt 时，称之为人工操作 brief。

demo 是可复现的兴趣模板与目录组合，不宣传为已经理解任意目标的实时推理。官方能力资料不是独立实测背书。不写虚构评分、评价、服务人数、收益或节省时长保证。

## 5. 交互与可访问性

当前兴趣、档位、金额、生成状态应可见。提交时禁重复点击，出错保留输入。Back/Forward、支付取消、对话框关闭后应能继续。提供标签、错误语义、键盘焦点和屏幕阅读器语义；移动端不横向溢出，尊重 reduced motion。外链打开后保留结果，不自动向工具上传用户信息。

## 6. 定价与成本假设

PREMIUM_PRICE_CENTS=299 是 demo 默认值。正式价格须由用户研究、费率、税费、退款规则与成本测量决定。原方案的价格区间、模型选择与费用预估不能直接成为当前报价。

单次贡献利润 = 收入（扣税后）－支付手续费－模型费用－邮件费用－可归属基础设施费用－退款/支持费用。

模型费用按实际 token、实际模型当前单价和失败重试测量；免费流量和滥用同样产生成本。真实供应商启用前应设预算与告警；代码不代表完整财务报表已经存在。

## 7. 验证指标（提案，无结果）

| 假设               | 指标定义                               | 用途           |
| ------------------ | -------------------------------------- | -------------- |
| 指导比链接列表有用 | 结果用户中尝试一个步骤的比例，访谈核对 | 是否加深教程   |
| 推荐与目标相关     | “适合目标”反馈与不相关原因             | 改目录与生成   |
| 有人愿意付费       | 成功真实 capture / 合格付费入口访问    | 验证价值与价格 |
| 用户愿意返回       | 7 天内复访或保存的去重用户比例         | 是否推进订阅   |
| 履约可靠           | 已付款未完成订单数和等待时间           | 暂停销售或修复 |
| 成本可持续         | 成功 Box 与失败重试的实际变动成本      | 配置免费额度   |

这些是待验证的产品假设，不是行业基准。管理端的第一方计数只能提供有限活动证据，尚不能直接回答任务完成、满意度、净收入或贡献利润。先做少量真实任务访谈和经同意的最小事件采集。采集前明确用途、接收方和保留期；不以大规模自动推广代替验证。
