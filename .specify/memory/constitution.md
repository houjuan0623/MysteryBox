# MysteryBox Constitution

## Core Principles

### I. 用户最新要求与可追溯交付

必须先维护需求、设计与验收，再将新行为标记为完成。用户最新明确要求优先于历史设计；`docs/source-plan.md` 是原始输入，必须逐字节保留，其 PostgreSQL 描述由 [ADR-008](../../docs/adr-latest-stack.md) 覆盖。项目仅包含 `apps/web`、`apps/admin`、`apps/api` 三个应用。不得因演示、MCP 或测试而增加第四个部署应用。每项变更必须对应功能需求、任务和当前证据。

### II. 独立应用与服务端权威边界

Web 与 Admin 必须分别使用 Next.js、shadcn/ui 与 Tailwind，并各自提供开发、构建、启动和部署边界。API 必须为独立 NestJS HTTP 服务。浏览器与 Next 代理不能决定金额、身份、角色、所有权、支付完成或模型供应商。数据库和业务供应商秘密只存在于 API。Admin 仅提供第一方只读用户/访客统计；每次服务端访问必须验证当前角色，隐藏导航不构成授权。

### III. 持久化、幂等与副作用安全

持久化必须使用 MongoDB 官方 Node.js 驱动以及支持多文档事务的 replica set；MemoryStore 仅用于明确标示的开发演示。相同业务幂等键必须绑定规范化输入和所有者；重复请求不得重复收费、生成资源或发邮件。事务自动重试不得隐式重放 PayPal、AI、邮件等外部副作用。提交结果不明确时必须保留稳定业务键和可恢复状态，不可声称成功，也不可生成新收费键。所有权、事务回滚、跨连接竞争和重启持久化必须有真实数据库测试。

### IV. 演示诚实、供应商与最小权限

默认 AI、支付、邮件均为 demo。真实 AI 唯一通道是 Vercel AI Gateway；历史 OpenAI 直连模式、分支和配置不得继续作为活跃支持。真实模型、密钥与调用授权未确定时不得发起真实推理。PayPal、邮件以及任何真实费用/外部发送均保留相应授权和验证门槛。MCP 仅为 Nest 内默认关闭的受控接口，只允许有 scope 的统计读取和草稿创建/列出；必须有审计及写操作幂等，不提供执行草稿、发送、收费或自动化。

### V. 可访问界面、中文工程说明与可信验证

产品界面使用英文；关键实现必须有解释业务与安全原因的中文注释，工程文档使用中文。动态交互必须尊重 reduced-motion，支持键盘、明确焦点和失败恢复。ESLint、Prettier、EditorConfig、TypeScript、单元、数据库、HTTP 和浏览器检查必须区分通过、失败、阻塞和未运行。旧主机测试、模拟供应商、局部代理测试、静态构建均不得代替新恢复版端到端结果。测试缺失不能以文档勾选掩盖。

## 范围与安全约束

- Free 提供 1 个工具；Premium 提供 3 个不重复工具、人工工作流与 Prompt。四个兴趣以及 16 个真实目录工具保持有效。
- 服务出售推荐与使用指导；不含第三方许可证、订阅、额度，不做抽奖。
- 生产数据库迁移、权限扩大、真实供应商调用、对外发送、收费、公开部署和 GitHub 发布必须分别处于已授权范围。
- 原始目标、邮箱、验证码、会话/访问令牌、密钥不得写入普通统计或 MCP 审计日志。访客标识不等同于真人身份。
- 本宪章首次采纳时实现尚未全部符合；差距必须保留为开放任务，而非修改原则以适应未完成代码。

## 开发流程与验收门槛

采用官方 github/spec-kit 1.2.0 的模板、命令提示与脚本。先维护 constitution，再按 specify → plan → tasks → implement → converge 的顺序推进；必要时进行 clarify、checklist 和 analyze。官方提示不自动授权额外操作。任何自动工作流都不得越过权限边界。

每次恢复或关键代码变更后重新验证受影响范围。完成报告必须给出命令、时间、结果、作用域及证据文件，区分报告转录与原始日志。功能 checklist 审查、代码实现、运行验证是三个不同层次。已有任务不得仅因骨架存在而勾选。

## Governance

本版本将已确定的用户要求转为工程约束，并未新增用户产品承诺。修订先记录原因、受影响需求和 ADR，保留原始输入，再同步 spec、plan、tasks、traceability 与验收。原则的破坏性变更升级主版本；新增原则升级次版本；澄清升级补丁版本。合并前审查宪章一致性；未解决的门槛只能报告为未完成，不得以口头豁免标为通过。
