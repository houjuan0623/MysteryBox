# Feature Specification: MysteryBox 三应用恢复与安全集成

**Feature Branch**: `001-three-app-foundation`（功能标识；本次未创建 Git 分支）

**Created**: 2026-10-14

**Status**: In progress；规格已编写，整体实现/集成尚未收敛

**Input**: 根据用户最新要求，将恢复工程落实为独立用户前台、管理端与业务 API，保留原始产品范围，完成数据库、认证、幂等、供应商与受控 MCP 的可验证实现。本文件表达目标，不将现有代码推定为已完成。

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 获得可理解且可操作的工具推荐 (Priority: P1)

访客选择 creator、developer、student 或 business，说明目标，领取 Free 推荐；结果提供具体理由、场景、Prompt、步骤和可信官方外链。

**Why this priority**: 无需付款即可验证产品的核心价值。

**Independent Test**: 仅启用 demo，选择四类兴趣分别提交，检查每份结果恰好 1 个目录工具；刷新和重试返回同一资源。

**Acceptance Scenarios**:

1. **Given** 有效兴趣与目标，**When** 首次提交 Free，**Then** 显示 1 个相关工具和完整操作指导，明确 demo 状态。
2. **Given** 同一业务键和输入，**When** 并发或网络重试，**Then** 不创建第二个资源；同键不同输入返回冲突。
3. **Given** 空目标、超过 500 字符或非法兴趣，**When** 提交，**Then** 给出清楚错误且保留可修改输入。
4. **Given** 键盘或 reduced-motion 使用者，**When** 浏览、开箱、复制与返回，**Then** 焦点可见、状态可理解，不强制持续运动。

### User Story 2 - 安全购买 Premium 指导 (Priority: P1)

用户清楚看到一次性服务价格、真实/模拟状态和第三方费用边界，完成付款或取消，获得 3 个不同工具及人工工作流。

**Why this priority**: 任何付费路径都必须优先保证金额、状态与重复请求安全。

**Independent Test**: 使用 demo 支付与模拟供应商响应运行订单创建、重复 capture、取消、失败恢复和 webhook 重放测试；不得据此声称真实收款通过。

**Acceptance Scenarios**:

1. **Given** 已显示服务端一次性 USD 价格，**When** 购买，**Then** 客户端不能覆盖价格；成功结果恰好 3 个不同目录工具，工作流只引用这 3 个工具。
2. **Given** 同单并发 capture、超时或重复 webhook，**When** 恢复处理，**Then** 不重复收费或交付，并保留可核对状态。
3. **Given** 支付未确认或取消，**When** 返回页面，**Then** 不冒称已付款，可返回编辑目标。

### User Story 3 - 登录并安全管理自己的内容 (Priority: P1)

用户通过邮箱验证码登录，认领自己的匿名内容，查看历史与收藏，并可退出。

**Why this priority**: 历史、付费资源和认领涉及用户所有权。

**Independent Test**: 两个用户加匿名访问者执行 OTP、认领、历史与收藏流程，验证跨用户读取/修改拒绝、验证码单次消费与退出失效。

**Acceptance Scenarios**:

1. **Given** 有效验证码，**When** 并发兑换，**Then** 只有合法的单次消费能建立会话，过期或重复兑换被拒绝。
2. **Given** 匿名内容及其合法凭据，**When** 用户认领，**Then** 只有该用户成为所有者，其他会话不能夺取或读取。
3. **Given** 有效用户会话，**When** 收藏、取消收藏、查看历史或退出，**Then** 状态持久化且始终按当前所有者授权。

### User Story 4 - 查看可信的只读运营统计 (Priority: P2)

管理员在独立管理端读取第一方用户及访客统计，明确时间窗、数据含义和模拟交易边界。

**Why this priority**: 提供运营可见性，同时避免暴露私人数据或扩大管理权限。

**Independent Test**: 分别以未登录、member、admin 访问报表；撤销角色后重用旧会话；验证 demo/sandbox/live 分类、UTC 窗口和事件去重。

**Acceptance Scenarios**:

1. **Given** 未登录或普通用户，**When** 直连 API 或管理端访问统计，**Then** 服务端拒绝。
2. **Given** 管理员角色已撤销，**When** 使用旧会话再次查询，**Then** 立即失去报表权限。
3. **Given** 无数据或重复事件，**When** 查询有效日期窗，**Then** 返回零/空集合且不重复计数；访客标识不称作独立真人。
4. **Given** demo 或 sandbox 付款，**When** 展示统计，**Then** 不计为真实收入。

### User Story 5 - 通过受控接口查询统计与管理草稿 (Priority: P2)

获准的 MCP 客户端只在显式启用后按 scope 查询统计，创建和列出草稿。草稿不会被自动执行、发布或发送。

**Why this priority**: 有限工具接口能够辅助运营，同时保持可审计、可撤销和最小权限。

**Independent Test**: 默认关闭、无凭据、错误 scope、重复写键、跨主体读取、审计脱敏以及未知工具拒绝；测试不得触发外部发送。

**Acceptance Scenarios**:

1. **Given** MCP 默认关闭，**When** 请求接口，**Then** 不暴露可调用业务能力。
2. **Given** 仅统计读取 scope，**When** 尝试创建草稿，**Then** 拒绝；不存在允许任意 HTTP、代码执行或发送的工具。
3. **Given** 相同主体、幂等键和草稿内容，**When** 重试创建，**Then** 返回同一草稿；同键不同内容冲突。
4. **Given** 草稿存在，**When** 列出，**Then** 只返回该授权主体可见的记录，并记录脱敏审计。

### User Story 6 - 可独立运行、复查与交接 (Priority: P1)

维护者可分别启动、构建和部署三个应用，按中文说明配置环境，并从规格追踪到验证结果。

**Why this priority**: 恢复后的代码必须能够交接，不能依赖旧主机或历史通过报告。

**Independent Test**: 单独构建和启动每个应用；仅按文档从干净环境执行配置、索引初始化、seed 与测试；检查原始计划校验和。

**Acceptance Scenarios**:

1. **Given** 仅启动 API，**When** 访问健康/业务接口，**Then** 不依赖任何 Next 进程。
2. **Given** 单独构建 Web 或 Admin，**When** 配置远程 API 地址，**Then** 不需要数据库或业务供应商秘密。
3. **Given** 当前恢复代码，**When** 查看完成报告，**Then** 明确区分通过、失败、阻塞、未运行和历史结果。

### Edge Cases

- MongoDB standalone、不可达或事务回滚：启动/验证明确失败，不能伪装成生产持久化。
- 数据库提交结果未知而外部操作可能已成功：保留原键、查询原状态，不自动再收费。
- 用户快速重复点击、刷新、关闭、Back/Forward、支付取消：状态可恢复，不能交付他人内容。
- AI 输出不存在的工具、重复 ID、额外字段或不合法工作流：校验拒绝，不绕过目录约束。
- 管理窗口坏日期、倒置或超过 31 天：明确拒绝；默认近 7 天，UTC 起含止不含。
- SMTP/Resend 或 AI 超时：不把演示输出标为真实送达/推理。
- MCP 未知方法、错误 scope、过大正文、无效写键：失败封闭并保留安全审计。

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 产品必须提供四个兴趣和 16 个真实目录工具；每个兴趣至少有 4 个候选。
- **FR-002**: Free 必须输出 1 个工具及理由、场景、Prompt、步骤；Premium 必须输出 3 个不重复工具和只引用所选工具的人工工作流。
- **FR-003**: 产品必须标示一次性服务价格、demo/真实状态和第三方费用边界；默认 demo 价格 USD 2.99，可由服务端配置。
- **FR-004**: 所有创建、支付、交付和草稿写入必须遵守稳定业务键、输入绑定与重复请求安全。
- **FR-005**: 支付金额、收款对象、订单归属、capture 和 webhook 结果必须由服务端验证。
- **FR-006**: 邮箱验证码必须限时、单次消费并建立安全会话；退出必须使会话失效。
- **FR-007**: 历史、收藏、匿名认领与付费内容必须始终按当前所有者授权。
- **FR-008**: 用户前台必须支持英文界面、移动布局、键盘、可见焦点、真实复制及 reduced-motion。
- **FR-009**: 前台必须对加载、失败、重试、支付取消、刷新与历史导航提供明确可恢复状态。
- **FR-010**: 管理端必须独立，提供只读第一方用户/访客统计，非管理员在服务端被拒绝。
- **FR-011**: 角色撤销必须对旧会话立即生效；浏览器输入不得赋予角色。
- **FR-012**: 统计必须统一 UTC 时间窗、事件去重、demo/sandbox/live 分类和 30 天活动清理；访客不能冒称真人，模拟付款不能冒称收入。
- **FR-013**: 邮件只在明确的用户请求和授权范围发送；demo 不真实发送，日志不暴露验证码或秘密。
- **FR-014**: 默认所有供应商均为 demo；真实 AI 只能走 Vercel AI Gateway，真实模型/密钥/授权门槛未满足时拒绝调用。
- **FR-015**: MCP 必须默认关闭并留在现有 API 内，按 scope 限制统计读取、草稿创建和草稿列出。
- **FR-016**: MCP 必须验证主体、隔离草稿所有权、对写入提供幂等及脱敏审计，不提供外部发送、执行、收费或自动化。
- **FR-017**: 每个应用必须可独立开发、构建、启动和部署；应用间只通过明确 HTTP 契约通信。
- **FR-018**: 持久化必须支持事务、业务唯一键、跨连接并发安全和进程重启恢复；外部副作用不随事务自动重放。
- **FR-019**: 工程必须有中文关键注释/文档，以及当前 ESLint、Prettier、EditorConfig、类型、测试和构建证据。
- **FR-020**: 必须保留原始计划、最新架构覆盖决策和官方 Spec Kit 来源；历史测试不得作为当前通过证据。

### Key Entities _(include if feature involves data)_

- Tool：目录 ID、兴趣、官方地址及可执行使用指导。
- Brief / Box：规范化目标、兴趣、等级、选定工具、工作流、所有者、生成模式与时间。
- User / Session / Verification：用户角色、认证状态、验证码消费、会话有效性。
- Order / Idempotency / Delivery：稳定业务键、输入指纹、付款状态、供应商引用及交付状态。
- Activity：最小必要的第一方事件、去重 ID、UTC 时间、模式；不保存原始目标/验证码/秘密。
- MCP Principal / Draft / Audit：作用域主体、草稿所有权与内容、写入键、脱敏操作结果。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 三个且仅三个应用均独立构建和启动，测试证据明确对应当前代码。
- **SC-002**: 四兴趣均可领取 1 工具 Free；Premium 恰好 3 个不重复工具；非法输出被拒绝。
- **SC-003**: 并发/重试测试不产生重复资源、重复收费或重复邮件；真实 replica-set 回滚、唯一约束及重启恢复通过。
- **SC-004**: 跨用户内容访问、匿名认领越权、普通用户管理访问、撤销角色后旧会话访问均被拒绝。
- **SC-005**: 无真实密钥/模型审批时外部调用数为零；demo UI 和统计不得宣称真实推理、收入或送达。
- **SC-006**: MCP 默认关闭；允许工具全集恰好覆盖 FR-015，scope/所有权/幂等/审计负例通过。
- **SC-007**: 所有 FR 均有任务和验收映射；原始计划 SHA-256 保持 `b2cd871409b4099d5f521c5e7b9875317fc139c966d033f15789581871738180`。

## Clarifications 与不做

最新确定的工程实现约束放在 [plan.md](plan.md)；本规格不重新选择已确定的数据库或框架。真实 Vercel 模型和凭据尚待用户选择/授权，但不阻塞 demo 集成验收。MCP 凭据发放、线上域名、生产基础设施仍是上线门槛，不推定已配置。

不做：第四个应用、自动 Agent 执行、增长自动化、订阅计费、社区、工具许可证转售、真实生产数据迁移或未授权上线。规格采用维护中的契约模式；新发现同步 plan/tasks/traceability，并保留验证记录时间。
